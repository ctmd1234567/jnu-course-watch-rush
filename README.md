# JNU Course Watch & Rush｜暨南大学蹲课抢课助手

面向暨南大学选课系统的 Windows 桌面助手：**全自动蹲课 + 定时自动抢课**。填入课程号、选择模式并启动后，程序会控制一个可见的浏览器窗口，自动进入选课、搜索课程、读取余量、点击选择和确认；只有账号密码、验证码、短信等必须由本人完成的认证才会暂停等待。

> 本项目不是暨南大学官方产品，与暨南大学及选课系统开发方无隶属或合作关系。请先确认学校规则允许自动化辅助操作，并自行核对课程、教师、时间冲突和实验班。

> **研究生系统大概率不可用：** 软件提供 `yjsxk.jnu.edu.cn` 研究生选课系统入口，并根据两个系统相似的 `xsxkapp` 框架尽力复用页面识别、课程搜索、翻页、选择确认和抢课预热流程。但目前没有研究生账号完成真实验证；只要 DOM、参数或提交函数存在差异就会失败，请不要把它当作已支持功能。

## 为什么方便

- **一次添加，多课托管**：蹲课和抢课可以放在同一张任务表中。
- **允许重复任务**：同一课程可以按不同模式、时间或教学班重复添加；学校确认已经选上后，相关任务会在各自检查时自动移出。
- **全流程自动**：登录有效时，自动进入“开始选课”、打开全校课程、搜索、判断余量、选择并确认。
- **同课号自动翻页**：原选课系统中同一课程号结果较多时，会继续检查后续页面，直到找到指定教学班或确认已经到末页。
- **抢课定时待机**：提前设置启动时间，程序在开抢前持续检查登录状态，到点立即执行，不增加整轮等待。
- **掉线自动恢复**：Session 失效后自动返回入口、点击登录和“开始选课”；统一认证仍有效时无需人工干预。
- **关闭即停止**：主动关闭受控浏览器会立即停止任务，不会把人工关闭误判为掉线并连续重开窗口。
- **始终单页面**：启动与关闭时清理独立 Profile 的标签恢复记录；网站打开新选课页后自动关闭旧入口页，Cookie 不受影响。
- **认证安全接管**：遇到账号密码、验证码、短信或其他人工认证时，保持受控浏览器打开并明显提醒，完成后自动恢复。
- **成功自动收尾**：选到的课程立即从活动表移出，剩余课程继续执行。
- **无需提供密码**：使用独立浏览器 Profile 保存正常 Cookie，不保存或填写账号密码。

## 浏览器与登录方式

程序优先使用 Windows 的系统默认 Chromium 浏览器；若默认浏览器无法被 Playwright 可靠控制，则优先回退到 Microsoft Edge，再尝试 Chrome 或其他受支持的 Chromium 浏览器。为避免个人 Profile 被锁定或损坏，程序会额外打开一个使用独立 Profile 的受控窗口，不会接管使用者原有的浏览器标签页。

- 首次运行通常需要在受控浏览器中重新登录；
- 若统一认证额外打开学校的“登录指南”页，程序会关闭指南并保留真正的身份验证页；
- 独立 Profile 会正常保存 Cookie，后续运行会尽量复用登录状态；
- Session 失效时，程序自动返回入口并点击登录或“开始选课”；
- 统一认证仍有效时会自动重新进入，不需要人工操作；
- 若出现账号密码、验证码、短信等人工认证，程序保持窗口打开、连续响铃并发送 Windows 通知；
- 使用者完成认证后，程序自动识别登录成功并恢复原任务。

## 可视化诊断中心

控制台顶部常驻显示完整运行链路：**受控浏览器 → 登录认证 → 选课页面 → 课程返回**。每一步都有独立状态，不需要使用者阅读终端日志猜测原因。

检测结果会明确归类并给出下一步：

- **学校网站/网络**：连接失败、加载超时、服务器 502/503/504，提示检查 VPN 或稍后重试；
- **人工认证**：密码、验证码或短信验证，响铃并通知用户到受控浏览器操作；
- **访问未授权**：学校明确显示“未获得本系统访问授权”时停止自动重试，并提示核对选课批次或联系教务部门；
- **页面适配**：学校 DOM 结构变化、关键控件消失，提示复制诊断信息反馈；
- **课程数据**：课程号或教学班未找到，提示核对输入或开放状态；
- **学校返回**：课程已满、冲突、禁用或弹窗拒绝，展示学校返回的容量和原因；
- **本机程序**：其他执行异常，保留脱敏技术详情并自动重试。

如果容量文字、可选标记和按钮状态互相矛盾，程序会标记“返回结果无法可靠识别”，本轮禁止自动点击，避免误选。点击“复制诊断信息”即可把不含 Cookie、token 和密码的状态发给维护者。

## 下载与安装

从 [GitHub Releases](https://github.com/ctmd1234567/jnu-course-watch-rush/releases/latest) 下载 Windows x64 文件：

- `JNU-Course-Watch-Rush-Setup-0.4.0-x64.exe`：安装版，可选择安装目录并创建桌面快捷方式；
- `JNU-Course-Watch-Rush-Portable-0.4.0-x64.exe`：便携版，双击直接运行。

首次启动可能出现 Windows SmartScreen 提示，因为个人构建没有购买代码签名证书。请只从本项目 Release 下载并自行核对文件；不放心时可按下方步骤从源码构建。

启动桌面程序后直接添加任务。点击“启动任务”会额外打开一个可见的受控浏览器窗口，首次需要登录时在该窗口中人工完成即可。未签名程序可能被 SmartScreen 或安全软件提示，请只从上方官方 Release 页面下载并核对校验值。

## 蹲课模式

适合持续等待课程放出余量：

- 默认每 20–30 秒随机检查一次；
- 建议范围 20–60 秒，程序允许 15–180 秒；
- 每轮都会正常触发全校课程搜索，读取最新数据，不会只反复读取旧 DOM；
- 一旦可选，自动点击学校页面的“选择”和“确认”。
- 课程号必填，教学班号可选；留空时匹配该课程下首个可选教学班。

## 抢课模式

每门抢课任务必须同时填写课程号、准确教学班号和启动时间。建议提前 2–5 分钟启动程序并完成统一认证。

开抢前，程序每秒观察任务与页面状态，并约每 20 秒通过正常页面刷新主动验证 Session：

1. 登录仍有效：保持选课系统待机；
2. 回到选课入口：自动点击登录或“开始选课”；
3. 统一认证仍有效：自动重新进入选课系统；
4. 出现验证码、账号密码或短信验证：播放提示音并等待用户完成；
5. 检测到重新登录成功：自动返回选课流程继续待机。

只要任务表中存在抢课任务，首次进入或真正重新登录进入选课系统后，会依次预热全部抢课任务；运行中新增的抢课任务也会在当前会话预热一次。纯蹲课任务不会触发这一步。同一任务在同一次有效会话不会每轮重复预热。进入开抢前 30 秒后停止待机刷新，并做一次最终预热，防止刷新与到点提交互相抢占页面。

到达启动时间后：

- 进入选课系统后先正常搜索并确认指定教学班；开抢前 30 秒再做一次最终预热；
- 到点使用学校页面当前 Session 和官方页面函数直接提交，不再先搜索；
- 预热失效或 Session 变化时自动重新预热，任务不会因此删除；
- 所有已到点的抢课任务优先立即执行；
- 不设置整轮重试间隔，读取一次状态后立即继续；
- 额外动作间隔默认 `0ms`，不设上下限；追求最快保持 0，页面不稳定时建议 `100–500ms`；
- 任务表直接显示预热搜索和直选提交耗时，便于判断瓶颈来自学校网站还是本机流程；
- 某门成功后立即移出，其他未成功课程继续；
- 执行中掉登录会自动恢复，然后继续未完成任务。
- 学校明确返回“达到/超过学分上限”时，程序会显示原始原因、响铃并停止整个任务引擎，浏览器保持打开。

程序坚持单浏览器、单 Session 操作，避免并发点击导致学校页面状态相互覆盖。实际速度主要取决于学校课程搜索和选课接口的响应时间。

## 自动化边界

项目不会：

- 保存或自动填写账号、密码；
- 绕过验证码、短信、CAS 或统一认证；
- 构造、保存或复用 `grablessons.do?token=...` 一类 URL；
- 伪造选课 POST、破解接口或并发轰炸服务器。

蹲课通过学校网页自己的 `.cv-choice` 和确认按钮操作；抢课预热后调用网页已经加载的官方参数构建与选课函数。两者都使用当前页面 Session，不保存或拼接 token，也不自行构造固定选课 URL。

## 从源码运行

要求 Windows 10/11、Node.js 20+，并安装 Microsoft Edge、Chrome 或其他受支持的 Chromium 浏览器：

```bat
git clone https://github.com/ctmd1234567/jnu-course-watch-rush.git
cd jnu-course-watch-rush
npm install
npm start
```

`npm start` 会直接打开独立的软件窗口，不需要也不建议手动访问端口网页。点击软件里的“启动任务”后，才会额外打开受控浏览器执行学校页面操作。

仅开发调试网页界面时才使用：

```bat
npm run start:web
```

此时开发页面位于 `http://127.0.0.1:3210`。

如果 VPN 导致统一认证超时，请关闭 VPN，或为 `*.jnu.edu.cn` 设置 DIRECT 规则。

## 构建 Windows 安装包和 EXE

```bat
npm install
npm run build:win
```

构建结果位于 `dist/`，同时包含 NSIS 安装版和 portable EXE。构建使用 Electron 自带的 Node 运行时，最终用户不需要另装 Node.js，但电脑上仍需安装受支持的 Chromium 浏览器（推荐 Microsoft Edge）。当前版本仅支持 Windows；macOS 需要单独适配与打包。

## 多教学班与实验班

- 填教学班号：只尝试对应教学班；
- 不填教学班号：在课程号匹配结果中选择第一个可选班；
- 包含实验教学班：默认暂停并要求人工确认；只有主动打开“自动选择首个实验班”后才会自动选择。

## 本地数据与隐私

源码运行时，状态保存在项目的 `runtime/`。安装版保存在当前 Windows 用户的应用数据目录。内容包括：

- `state.json`：任务和频率设置；
- `browser-profile/`：受控浏览器 Cookie 与正常登录状态。

这些内容不会被 Git 跟踪。不要上传、分享或打包自己的运行时目录。要清除登录状态，请先退出程序，再删除对应的 `browser-profile/`。

## 当前页面适配

- **原选课系统（`jwxk.jnu.edu.cn`）**：已依据实际 DOM 适配全校课程标签、搜索框、课程列表、选择按钮和确认弹窗。
- **研究生选课系统（`yjsxk.jnu.edu.cn`）**：具有独立入口、独立会话和独立 adapter，但当前 adapter 只是对相似 `xsxkapp` 页面结构与函数的尽力兼容，未经研究生账号验证，**大概率不可用**。如果页面无法识别，会显示 `graduate_page_unknown` 并生成脱敏诊断；如果页面看似相同但接口参数或业务规则不同，搜索或提交仍可能失败。

学校升级页面后结构也可能改变。请使用软件中的“复制诊断信息”提交自动脱敏后的结构摘要；不要自行提交 Cookie、token、学号、密码、请求正文、响应正文或完整页面 HTML。
